Saklolo — Wireframes

Every screen and state in USER-FLOW.md. Low-fidelity layout; names, numbers and times are sample data. Tags: MUSTWOWSTRETCHTBD — orange TBD means the sources don't decide it, so the wireframe shows a proposal.

A. Launch

What the user sees first, every time the app opens. Proposed: a plain splash that never waits for the model. First launch: four Welcome slides (skippable), then Setup. Otherwise Home.
A1. SplashMUSTPROPOSED
Static launch screen. Same ground color as Home. About 1 s, no animation, nothing to tap.
SAKLOLO
Only the mark and the name. No progress, timer or buttons, so it can never block an alert. When Saklolo is opened from a Lock Screen, Control Center or Action Button control, the splash, Welcome and Home are skipped and Listening (F1) starts at once. The model loads in the background (see E2). Next: Home if setup is done, otherwise the Welcome slides (A2). TBD: whether to skip the splash and use the iOS launch screen alone; where the first-run model load happens (onboarding, bundled, or background).

Tapping the red button on Home (E1) morphs it into the orb at the bottom, with no screen change. When Saklolo is opened from a control, this screen appears directly (K5). Nothing is sent or announced at the tap, so the user is not alarmed. The phone listens and understands first. A quiet ✕ Cancel in the header stops an accidental start with no text sent. The Shortcut fails or is missing → card in the chat, then the message composer (I1, I2)
No cell signal → text queued, retried every 30 s, guidance keeps working (I3)
No GPS → last known location, labelled as such (I4)
Speech-to-text fails or is empty → general alert after 10 s, then typed input (F5, F6)
Model not ready or loading → keyword classifier; the red button and typing still work (E2)
Local AI slow, blocked or wrong → keyword result is used; “Not right?” corrects it (F4)
Microphone off → typed input and the buttons (E4, G7)
No voice → the text is always on screen; an English voice is built into iOS, so no recorded clips are needed
Call needs a tap → iOS asks to confirm; the text has already gone (G8)
Order of the understanding chain: keyword classifier first, local AI refines it, the general script is last (F7). The text never waits for any of them past 10 s.
